# 脱敏与发布检查清单（Desensitize Checklist）

两个用途：**A. 自己部署时**防止真实值进入任何会共享的文件；**B. 开源发布前**终审。
两道工序缺一不可：①逐项核对映射表；②grep 机械复查（机械替换一定会漏，grep 是兜底）。

## A. 字段映射表（部署/改造时逐项核对）

把每一个真实值替换为占位符。本仓库内只允许出现右列；左列的真值清单
**写在仓库之外的私有文件里**（例如放本机笔记，永不提交）。

| 类别 | 真值特征 | 发布版占位 |
|---|---|---|
| 群 ID | `oc_` 开头长串 | `oc_replace_with_your_group_chat_id` |
| 用户身份 | `ou_` 开头长串 | `ou_replace_with_your_open_id` |
| Bot 应用名 | `cli_` 开头长串 | 示例中不出现，指向 config 字段 |
| 记忆库 token | 20+ 位随机串 | config 字段留空 |
| 记忆表 ID | `tbl` 开头串 | config 字段留空 |
| 协议记录 ID | `rec` 开头串 | 文档不引用，改为转述条文 |
| 机器名 | 真名/品牌/硬件型号 | `machine-a` / `machine-b` |
| 软件名 | 各 agent 私有命名 | `my-agent` |
| 消息前缀 | `【真实机器名-软件名】` | `【machine-a-my-agent】` |
| 本机绝对路径 | `D:\...`、`C:\Users\<你>\...` | `%USERPROFILE%`、相对路径 |
| 示例消息/截图 | 可能内嵌以上任意项 | 全部改写为剧本（见 examples/） |
| 记忆条目内容 | 项目名、单位、客户、业务事实 | 不搬运，协议文档只写字段设计 |

**特别提醒（历史教训位）**：机器名会渗透到**不相关文件**里（其他 skill 文档、
巡检白名单、示例输出）。发布范围之外的同名残留不归本仓库管，但发布前应顺手排查
待发布目录的引用源。

## B. grep 机械复查（发布前必跑，全零才算过）

在待发布仓库根目录执行（Git Bash）：

```bash
# 1) IM 各类 ID（oc_/ou_/cli_/rec_ 前缀长串）
grep -rInE "\b(oc|ou|cli|rec)_[A-Za-z0-9]{10,}" .

# 2) 疑似 token（20+ 位连续字母数字，人工过目确认全是示例占位）
grep -rInE "[A-Za-z0-9]{22,}" .

# 3) 示例消息里的机器前缀（只允许出现占位代称，人工过目）
grep -rInE "【[^】]+】" .

# 4) Windows 绝对路径
grep -rInE "[A-Z]:\\\\" .

# 5) 机器代称黑名单 —— 黑名单内容放在仓库外私有文件里，此处引用之：
#    grep -rInf ~/.private/machine-aliases.txt .
```

任何一条非零命中：回看 A 表定位类别 → 修正 → 重跑，直到全零。

## C. 内容面自查（grep 管不住的部分）

- [ ] 示例对话/截图是否全部改写为剧本（群里真实聊天记录永不入库）
- [ ] 记忆条目示例是否只含协议字段设计，不含任何业务事实
- [ ] 文档中「我/我们」的叙述是否泄露行业、单位、客户信息
- [ ] git 历史是否干净（建议：全新 init 提交，不携带任何历史）
- [ ] config.example.json 全字段是否为占位符（含 `_comment` 说明字段）
